## 1. Goal / 何を作るか

<goal>
球体 (Isolation Sphere V2) の**北極キャップを、電源状態と充電状態が見える「ステータス窓」に作り替える。**

解決する問題は 2 つ:

1. **電源 ON/OFF が分からない** — 磁石をかざして電源を入れても、コントローラ (M5 AtomS 系) の起動に時間がかかるため、
   その間ユーザーは ON なのか OFF なのか判断できない。**ファームウェアに依存しないハードウェア表示**が必要。
2. **既存の指示 LED が見えない** — [`docs/06`](06-power-switch.md) §3.6.2 の電源 ON LED と
   [`docs/02`](02-ip2326-module.md) §3.5 の充電中 LED は**どちらも電源基板上 = 球体コアの中**にあり、
   外殻に埋まって視認できない。**北極キャップへ移設する。**

加えて **「再生が始まったら消灯する」** — コントローラがコンテンツ再生を開始したら、
ステータス窓を消して演出の邪魔をしない。これは ESP32 からの veto 線 1 本で実現する (§4.3)。
</goal>

## 4. Electrical specification / 電気仕様

### 4.1 System context (前提となる電源アーキテクチャ)

```
2S LiPo ──> [XR-2S-30A BMS (基板外)] ──> PACK_P (6.0-8.4V)
                                            │
                        ┌───────────────────┼──────────────────┐
                        │                   │                  │
                   [IP2326 充電]      [HT7333-1 LDO]     [MP1584 降圧]
                   CHG_IN=南極磁気端子   3.3V 常時オン        EN 制御で ON/OFF
                        │                   │                  │
                    pin6=充電LED        ┌───┴───┐            V5V (5V/3A)
                        │               │       │                │
                        │          ホール素子  [D-FF]            └─> AtomS + LED 800
                        │           (北極)   Q=電源状態
                        │                       │
                        └──────────────> 北極ステータス窓 <───────┘
```

**重要**: 3.3 V LDO は**常時オン**。だから電源 OFF 中でもホール素子と D-FF が生きていて、
かざした瞬間に反応できる。この構造が本 doc の前提。詳細は [`docs/06`](06-power-switch.md)。

### 4.2 北極 pillar を通る配線 — 6 本

| # | 信号名 | 方向 | 内容 |
| --- | --- | --- | --- |
| 1 | `V3P3` | 基板 → 北極 | 常時オン 3.3 V。**ホール素子専用** (veto の影響を受けてはならない) |
| 2 | `GND` | — | 共通グランド |
| 3 | `HALL_OUT` | 北極 → 基板 | ホール素子出力 (磁石検出) → D-FF の CLK |
| 4 | `LED_VCC` | 基板 → 北極 | **veto でゲートされた LED 用アノード共通レール** (§4.3)。2 灯を一括で消す |
| 5 | `STAT_PWR_K` | 北極 → 基板 | 電源 ON LED のカソード側戻り (基板側で Q によりスイッチ) |
| 6 | `STAT_CHG_K` | 北極 → 基板 | 充電 LED のカソード側戻り → IP2326 pin 6 |

- **線材: AWG30 級の細線 × 6**。AWG30 は被覆込み Φ0.5 mm 級なので Φ3 mm (断面 7 mm²) 通路に余裕で収まる
- ⚠️ **`V3P3` と `LED_VCC` を共用してはならない** — 共用するとホール素子が veto 中に停止し、
  再生中に磁石をかざしても電源が切れなくなる
- **`HALL_OUT` は必ずツイストする** — 球内に WS2812 データ 5 本が走っており、
  40〜50 mm の引き回しはノイズを拾う。ホール出力はドライブされた低インピーダンスなので
  リードスイッチ (高インピーダンスのプルアップノード) よりは有利だが、対策は入れる
- 基板側に **RC ローパス** (例 1 kΩ + 1 nF) を入れる

### 4.3 インジケータの駆動 + 再生開始で 2 灯とも消灯する仕組み (veto)

**電流制限抵抗と LED はキャリア基板に、スイッチング素子は電源基板に置く。**

**設計方針: veto は「LED 用アノードレール `LED_VCC` を 1 個の素子で切る」。**
こうすれば **電源 ON LED と充電 LED の 2 灯を 1 箇所で一括消灯**でき、
IP2326 pin 6 の駆動経路に一切手を入れずに済む (pin 6 の駆動形式が §7 Q2 で未確定なため重要)。

```text
                    [電源基板]                          │      [キャリア基板 = 北極]
                                                        │
  V3P3 ──┬─────────────────────────────────────────────┼──> ホール素子 (veto の影響を受けない)
         │                                              │
         ├── Q_RAIL.source (P-MOS)                      │
         │      │  gate ──┬── R 100k ── GND  (default ON = 点灯)
         │      │         └── R 10k ──── VETO 信号 (H で OFF = 消灯)
         │      │                                       │
         │   Q_RAIL.drain ── LED_VCC ══════════════════>┼──┬── R 680Ω ── LED_PWR ──┐
         │                                              │  │  (Vf 2.0V → 2.0mA)    │
         │                                              │  └── R xxxΩ ── LED_CHG ──┼─┐
         │                                              │     (値は §7 Q2 で確定)  │ │
         │   Q_LED.drain <════ STAT_PWR_K ══════════════┼─────────────────────────-┘ │
         │      │ (2N7002)                              │                            │
         │     GND                                      │                            │
         │      gate ── R 10k ── Q (D-FF 出力)          │                            │
         │                                              │                            │
         └── IP2326 pin 6 <════ STAT_CHG_K ═════════════┼────────────────────────────┘
```

**`VETO` 信号の作り方は 3 案あり (下記)。上の骨格はどの案でも共通。**

⚠️ **`Q_RAIL` の gate は R 100k で GND へプルダウンする (default = 点灯)。**
これが boot-safe を保証する — AtomS3R が起動中で veto を driveできない間、
LED レールは生きたままになる。**このプルダウンは省略不可。**

#### ⚠️ 制約: M5 AtomS3R は GPIO を使い切っている (2026-08-11)

当初案の「ESP32 の GPIO 1 本で veto」は**使えない**。代替 3 案を比較する。

| | **案 A: WS2812 データ活動検出** | 案 B: I2C GPIO エキスパンダ | 案 C: RC タイムアウト |
| --- | --- | --- | --- |
| GPIO 消費 | **0** | **0** (既存 I2C バスに相乗り) | **0** |
| firmware 変更 | **不要** | 必要 (1 bit 書くだけ) | **不要** |
| 追加部品 | 6 点 (すべて既存 BOM の型番) | IC 1 個 + 受動数点 + アドレス管理 | **4 点** |
| 消灯タイミング | **WS2812 へフレームが流れ始めた瞬間** | firmware が決めた任意の時点 | 電源 ON から固定時間後 |
| 意味的な正しさ | **「再生を始めたら」とほぼ一致** | 最も正確 (任意の条件で制御可) | 近似 (起動が遅れると先に消える) |
| リスク | データ線への負荷 (要高インピーダンス設計) | I2C バスが GPIO として使われていると成立しない | 起動時間のばらつきを吸収できない |

**推奨は案 A。** GPIO も I2C も firmware も使わず、しかも「再生が始まった」という
意味そのものを直接検出できる。

#### 案 A の回路 (WS2812 データ活動検出) — **フォールバック**

⚠️ **2026-08-11 に方針変更: I2C 端子が基板上で使用可能と判明したため、`VETO` は
§4.4 案 1 (I2C GPIO エキスパンダ) から取る。** 案 A は **I2C が使えないと分かった場合の
代替**として残す (定数まで算出済みなので即着手できる)。

Grove ポートは BNO055 が使用中だが、**I2C はバスなので別アドレスのデバイスを追加できる**
(§4.4)。案 A を使うのは、アドレス衝突・バス速度・実装スペースなどで
エキスパンダが載らないと判明した場合に限る。

##### ① 入力信号の実測前提 (WS2812 のタイミングから計算)

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| ビット周期 | **1.25 µs** (800 kbps) | WS2812 プロトコル |
| **High の最大継続時間** | **T1H ≈ 0.8 µs** (公差込みで 1 µs 未満) | 「持続 High は通常発生しない」ことの根拠 |
| バースト内のデューティ | **28%** (全ビット 0) 〜 **60%** (全ビット 1) | T0H 0.4 / T1H 0.8 ÷ 1.25 |
| **1 フレームの送出時間** | **4.8 ms** | 160 LED × 24 bit × 1.25 µs。**5 本は並列駆動なので 1 本ぶんの時間** |
| フレーム間隔 (30 fps 想定) | 33.3 ms | — |
| **「データあり」の実効デューティ** | **4.0%** (全 0) 〜 **8.6%** (全 1) | 4.8 ms × バースト内デューティ ÷ 33.3 ms |

**設計は最悪条件 (実効デューティ 4.0% = 全ビット 0 = 全消灯フレーム) で成立させる。**

##### ② 回路

```text
  WS2812 DIN ──[R1 100k]──┬──[D1 1N4148W]──┬── V_ACT ──[R3 1M]── Q_ACT.base
   (3.3V, 800kbps)        │                │                     (MMBT3904 / C20526)
                          │             C1 100nF                        │
                       ピーク電流         │                       Q_ACT.collector
                       33 µA のみ       R2 4.7M                        │
                       = 信号品質に       │                        VETO ノード
                       影響しない        GND
```

##### ③ 定数の根拠

| 項目 | 式 / 値 |
| --- | --- |
| 充電の実効時定数 | `τc = R1·C1 / 実効デューティ` = 10 ms / 0.040 = **250 ms** |
| 放電の時定数 | `τd = R2·C1` = 4.7 MΩ × 100 nF = **470 ms** |
| `V_ACT` の平衡電圧 | `(3.3 − Vf) × τd/(τd+τc)` = 2.7 × 470/720 = **1.76 V** |
| しきい値 | **NPN の Vbe = 0.6 V** |
| **余裕** | 1.76 / 0.6 = **2.9 倍** ✓ |
| 消灯までの時間 | 数フレーム (≈100 ms 以内) |
| **再点灯までの時間** | `τd × ln(1.76/0.6)` = **約 0.5 s** |

- **しきい値に NPN の Vbe (0.6 V) を使う。** MOSFET の Vth (2N7002 で 1.0〜2.5 V の 2.5 倍ばらつき)
  に依存させない — [`docs/06`](06-power-switch.md) §3.6.4 で採った設計方針と同じ
- `R3 = 1 MΩ` にして **`V_ACT` からの引き出しを 1.2 µA に抑える**。
  こうすればチャージポンプの供給能力 (1 フレームあたり 40 nC 級) で余裕をもって支えられる。
  ⚠️ `R3` を 10 kΩ にすると 120 µA を引いてポンプが追従できず**平衡電圧が崩壊する**
- **`R1 = 100 kΩ` でデータ線への負荷はピーク 33 µA のみ。** ESP32 GPIO の駆動能力
  (20〜40 mA) に対して 0.1% 以下で、信号品質に影響しない
- **部品はすべて既存 BOM の型番を流用できる**: MMBT3904 = `C20526` /
  1N4148W = MP1584 の BST ダイオード `D3` と同型 / 抵抗・コンデンサは 0603 の既存品番
- **オフ時電流は 0** — `V_ACT` が 0 V なので `R2` にも `R3` にも電流が流れない

##### ④ VETO の極性と出力段 — **IP2326 pin 6 の駆動形式で 2 通りに分かれる (§7 Q2)**

`Q_ACT` (NPN) は **GND へ引く**ことしかできない。一方 boot-safe の要件から
**「detector 非活性 = 点灯」がデフォルト**でなければならない。この組み合わせで topology が決まる。

| pin 6 が | LED の共通側 | veto 素子 | 極性の整合 | 追加部品 |
| --- | --- | --- | --- | --- |
| **ソース (吐き出し)** | **共通カソード → GND** | **N-MOS 1 個** (ゲートを V3P3 へ 100 kΩ でプルアップ = default ON) | **`Q_ACT` がゲートを引き下げて消灯 — 直結で成立** ✓ | N-MOS + R 100 kΩ = **2 点** |
| **シンク (吸い込み)** | **共通アノード `LED_VCC`** | **P-MOS** (§4.3 の骨格) | `Q_ACT` では P-MOS ゲートを V3P3 まで**持ち上げられない** → **PNP 1 石の反転段が必要** | P-MOS + PNP + R×3 = **5 点** |

**pin 6 がソースなら回路が 3 点少なく済む。** §7 Q2 を先に確定させること。

##### ⑤ 実装上の注意

- **タップするのは 5 本のうち 1 本。** 常に駆動される系統を選ぶ
  (一部の系統だけ止める実装があると誤検出する)
- **タップ線は 50 mm 以下に抑える。** 800 kbps に対する容量負荷は
  50 mm ≈ 5 pF 程度で問題にならないが、長くする場合は `R1` をタップ点側に置く
- **電源基板に WS2812 データ線のタップ入力が 1 本増える** — コネクタ 1 ピンを確保する
  ([`docs/01`](01-legacy-analysis.md) §4 のコネクタ構成に反映)
- **この同じタップは将来 `PWR_OFF` にも再利用できる** — WS2812 は High が
  0.8 µs しか続かないので、**数十 ms の持続 High は通常動作では絶対に起きない**一意な合図になる。
  ただし `V_ACT` は持続 High でも飽和するため、**判別には 2 段目のしきい値が必要** (§4.4 案 2)

⚠️ **案 A の意味論に注意**: 検出しているのは「**firmware が WS2812 フレームを送出している**」で、
「コンテンツを再生している」ではない。**firmware が待機中も黒フレームを流し続ける実装だと、
待機状態でも消灯する。** ファームウェアの挙動を確認して判断すること (§7 V3)。

#### 動作表 (案 A の場合)

| 状態 | Q | VETO | 電源 ON LED | 充電 LED |
| --- | --- | --- | --- | --- |
| 電源 OFF・充電なし | L | L | 消灯 | 消灯 |
| **電源 OFF で充電中** | L | L | 消灯 | **点灯** ← 消灯のまま充電できることの可視化 |
| **かざした瞬間 〜 AtomS 起動中** | **H** | **L** | **点灯** ← 解決したい問題 | 充電中なら点灯 |
| **動画再生中** | H | **H** | **消灯** | **消灯** ← 2 灯とも消える (2026-08-11 確定) |
| 再生停止 / 送出が 100 ms 以上途切れた | H | L | 点灯 | 充電中なら点灯 |

**boot-safe が最重要要件**: `Q_RAIL.gate` の pulldown が無いと `VETO` ノードが不定電位になり、
起動中に消灯する事故が起きる。**どの案を選んでも pulldown は省略不可。**

### 4.4 ESP32 インターフェースと GPIO 拡張

<constraint>
**M5 AtomS3R は GPIO を使い切っており、veto 線も電源オフ線も割り当てられない (2026-08-11)。**
必要な信号は 2 本:

| 信号 | 方向 | 用途 | 現在の扱い |
| --- | --- | --- | --- |
| `VETO` | AtomS → 基板 | 再生開始でステータス窓を消灯 (§4.3) | 本 doc で新設 |
| `PWR_OFF` | AtomS → 基板 | ソフト電源断 (D-FF の CLR を引く) | **2026-08-11 にペンディング解除 → 実装する** ([`docs/06`](06-power-switch.md) §1 の「パッド予約のみ」を改訂) |

**GPIO は 1 本も空いていないが、I2C 端子が基板上に実装済みで使用可能** (2026-08-11 ユーザー確認)。
I2C は**バス**なので、Grove の BNO055 と同居しながらデバイスを追加でき、**GPIO を消費しない。**
</constraint>

#### 拡張方法 3 案

| | **案 1: I2C GPIO エキスパンダ** | 案 2: WS2812 データ線に多重化 | 案 3: コントローラを載せ替え |
| --- | --- | --- | --- |
| 追加 GPIO の消費 | **0** (既存 I2C バスに相乗り) | **0** | — |
| 得られるビット数 | **4〜8 本** (将来の拡張余地つき) | 1 本相当 | 多数 |
| 部品 | IC 1 個 + パスコン (I2C プルアップはバス側に既存) | R + D + C + NPN ≈ 4 点 | — |
| firmware | I2C 書き込み (M5Unified で容易) | `digitalWrite(HIGH); delay(100);` のみ | 再検証が必要 |
| 決定性 | **高い** (任意のタイミングを明示的に制御) | 中 (レベル判別に設計余裕が必要) | 高い |
| 前提 | **I2C バスが空いていること** ← §7 Q5 | WS2812 線を電源基板まで引くこと | 親プロジェクトへの影響大 |

#### 案 1 で確定 (2026-08-11 ユーザー確認)

**I2C 端子は電源基板上に実装済みで使用可能**、かつ **`PWR_OFF` も実現したい**との判断。

> **Grove を BNO055 が使っていても問題ない。** I2C は**バス**なので、同じ 2 線に別アドレスの
> デバイスを追加できる (BNO055 = 0x28/0x29、エキスパンダ = 0x20 帯 / 0x41)。**GPIO は 1 本も増えない。**

これにより **`VETO` と `PWR_OFF` を 1 個の IC でまとめて供給**でき、
**§4.3 案 A (WS2812 データ活動検出) は不要になる** → 案 A は **I2C が使えなかった場合の
フォールバックとして残す** (回路と定数は算出済みなので、必要になれば即着手できる)。

##### 信号の割り当て

| ビット | 信号 | 極性 | 接続先 |
| --- | --- | --- | --- |
| P0 | `VETO` | 詳細は下記 ② | LED アノードレール `LED_VCC` のスイッチ (§4.3) |
| P1 | `PWR_OFF` | 同 | D-FF の **CLR (アクティブ Low)** → 引くと即 OFF |
| P2, P3 | 予備 | — | 将来の `PWR_STATE` 通知 / RGB ドライバ制御など |

##### ① ⚠️ 落とし穴 1: 電源ドメインの選択

| 電源 | 利点 | 致命的な問題 |
| --- | --- | --- |
| **常時オン 3.3 V (`V3P3`)** | 配線が単純 | **前回セッションの veto 状態が残る。** 再生中に電源を切ると veto=有効のまま保持され、**次回起動時にステータス窓が点かない** — 本 doc が解決しようとしている問題そのものが再発する |
| **電源 ON 中の系 (推奨)** | **毎回リセットされるので状態が残らない** ✓ / **オフ時電流に寄与しない** ✓ | 未通電時のリーク経路に注意 (下記 ②) |

**推奨: AtomS3R の 3V3 出力から給電する。** I2C バスの論理レベルも AtomS3R の 3.3 V と
自動的に一致するので、レベル変換が不要になる (§7 V8 で 3V3 ピンの供給能力を確認)。

##### ② ⚠️ 落とし穴 2: 未通電時のリークと power-up 出力状態

エキスパンダを ON ドメインで動かすと、**電源 OFF 中はエキスパンダが未通電**になる。
このとき信号線を常時オン側のプルアップで保持すると、
**プルアップ電流が未通電 IC の ESD ダイオード経由で VDD へ流れ込む** — 100 kΩ × 2 本で
**66 µA**、オフ時電流の予算 50 µA を単独で超える。

**対策: エキスパンダの出力を直接つながず、小信号 N-MOS 1 石ずつで受ける。**

```text
   [ON ドメイン]                    │        [常時オン ドメイン]
                                    │
  エキスパンダ Px ──┬── R 10k ──────┼── Q_x.gate      (Q_x = 2N7002)
                    │               │      │
                  R 100k            │   Q_x.drain ──> 信号ノード
                  (pulldown)        │      │          (VETO / CLR)
                    │               │     GND         ← R 100k で V3P3 へプルアップ
                   GND              │
```

- **未通電時**: `Px` が高インピーダンス → `R 100k` の pulldown が `Q_x` のゲートを GND に固定
  → `Q_x` OFF → **リーク経路なし** ✓ かつ信号ノードはプルアップで H = 非アサート ✓
- **極性**: エキスパンダが **H を出すとアサート** (`Q_x` が信号を GND へ引く) になる
- **したがってエキスパンダは「power-up 時に出力が H にならない」品種でなければならない。**
  **`PCA9536` は power-up 時に全ピンが入力 (高インピーダンス) になる**ので条件を満たす。
  ⚠️ **`PCF8574` は power-up 時に出力が H** になるため、この topology では
  **起動と同時に電源が切れる**。**PCF8574 を採用してはならない** (§7 V7 で最終確認)
- pulldown があるので **boot-safe も同時に満たす** — firmware が走る前は両信号とも非アサート
  = ステータス窓は点灯、電源は入ったまま ✓

##### ③ `PWR_OFF` の動作シーケンス

1. firmware が `P1` を H にする → `Q_1` が D-FF の `CLR` を GND へ引く
2. D-FF がクリア → `Q` = L → MP1584 の EN が L → 5V 崩壊 → **電源 OFF**
3. 5V が消える → AtomS3R とエキスパンダが未通電 → `Q_1` OFF → `CLR` はプルアップで解放
4. **D-FF は常時オン 3.3 V で生きており `Q` = L を保持** → 再投入ループは起きない ✓

##### ④ 部品と追加線

| 部品 | 数 | 置き場所 |
| --- | --- | --- |
| I2C GPIO エキスパンダ (PCA9536 系) | 1 | 電源基板 |
| パスコン 100 nF | 1 | 電源基板 |
| N-MOS 2N7002 (`C8545`) | 2 | 電源基板 |
| 抵抗 (ゲート直列 10 k ×2 / pulldown 100 k ×2 / プルアップ 100 k ×2) | 6 | 電源基板 |

- **AtomS3R との接続線: SDA / SCL / 3V3 / GND = 4 本** (既存 I2C 端子を流用)
- I2C バスのプルアップ抵抗が基板側にあるか AtomS3R 側にあるかを確認 (§7 V9)

#### 案 2 の詳細 (I2C が使えなかった場合の代替)

WS2812 のプロトコルでは **High が最大 ~0.9 µs (T1H) しか続かない**。
したがって **数十 ms continuous High は通常動作では絶対に発生しない** → 一意な合図として使える。

- firmware は該当ピンを `HIGH` にして 100 ms 保持するだけ
- 基板側は RC ローパス + NPN で「持続 High」を検出 → `PWR_OFF` を生成
- ⚠️ **通常のフレーム送出との判別に設計余裕が必要**: WS2812 のビット列はデューティ
  33〜66% なので、RC の整定値が全ビット 1 のときと持続 High で近づく。
  **しきい値の余裕を計算で裏取りすること**。余裕が取れない場合は案 1 に戻る

### 4.5 充電中 LED

- IP2326 **pin 6** が駆動 (充電中点灯 / 満充電消灯 / 異常点滅を IC が自動判定)
- アノードは **`LED_VCC`** から取る。`LED_VCC` は常時オンの `V3P3` を veto でゲートしたものなので:
  - **電源 OFF 中の充電でも点灯する** ✓ (「消灯のまま充電できる」ことがユーザーに見える)
  - **動画再生中は電源 ON LED と一緒に消灯する** ✓ (2026-08-11 確定)
- 直列抵抗はキャリア基板側に置く。値は pin 6 の駆動形式が確定してから決める (§7 Q2)
- ⚠️ **異常表示は別 LED を足さなくてよい** — IP2326 が**異常時に点滅**させるので、
  この 1 灯が「充電中 / 満充電 / 異常」の 3 状態を表現する

### 4.6 ホール素子

| 候補 | 消費電流 | Bop | パッケージ | 調達 | 備考 |

  プルアップ 100 kΩ でのリーク (LVC 入力リーク ±1 µA max) を確認
- **V5: pillar 先端の実寸** — キャリア基板の外形が決まる。親 `docs/01-shell-cad.md` を参照
- **V6: HT7333-1 の入力電圧上限**が 2S 8.4 V に対し十分か (LCSC 表記 30 V を datasheet で裏取り)
</open_questions>

## 8. Acceptance criteria / 完了条件

- [ ] **磁石をかざした瞬間** (AtomS の起動を待たず) に北極が点灯する
- [ ] **起動中も点灯し続ける** — AtomS の GPIO が High-Z の間、pulldown で LED が生きている
- [ ] **再生開始で消灯する** — §4.4 で選んだ方式 (I2C エキスパンダ / データ活動検出 / タイムアウト) で消える
- [ ] **veto 経路が AtomS3R の GPIO を 1 本も新規に消費していない** (§4.4 の前提)
- [ ] **もう一度かざすと即座に消灯**し、電源が切れる
- [ ] **firmware から I2C 経由で電源を切れる** (`PWR_OFF`)。切れた後に再投入ループが起きない
- [ ] **電源 OFF 中のリーク経路が無い** — エキスパンダ未通電時にプルアップ電流が
      ESD ダイオードへ流れ込んでいないこと (実測でオフ時電流を確認)
- [ ] **エキスパンダの power-up 出力状態で誤動作しない** — 起動と同時に
      電源が切れたりステータス窓が消えたりしないこと
- [ ] **電池を挿した直後は消灯 (電源 OFF)** — D-FF の POR で保証
- [ ] **電源 OFF のまま充電すると充電 LED だけが点く**
- [ ] **動画再生中は電源 ON LED と充電 LED の両方が消灯する**
- [ ] **ホール素子は veto 中も動作している** — 再生中に磁石をかざして電源を切れること
      (`V3P3` と `LED_VCC` を共用していないことの確認)
- [ ] **南極の充電マグネットを着脱してもホール素子が誤反応しない**
- [ ] オフ時のシステム合計電流が **≤50 µA** (設計見込み: LDO 2.5 + ホール 1.6〜4.0 + D-FF ~1 + MP1584 12 + IP2326 0.7 ≈ **18〜21 µA typ**)
- [ ] **北極キャップを外しても配線を触らずに済む** (素子は pillar 側)
- [ ] **接着剤を 1 箇所も使っていない**

## 9. Hard rules / 厳守事項

<hard_rules>
- **NEVER** 接着剤・瞬間接着剤・エポキシで固定する (親プロジェクトの全損事故履歴)
- **NEVER** 連続動作型のホール IC (mA 級) を使う — オフ電流予算 50 µA を 100 倍超える
- **NEVER** ホールラッチ (bipolar latch) を使う — 磁石を裏返す操作が必要になり UX が成立しない
- **NEVER** MP1584 の EN を 2S レール (6.0〜8.4 V) に接続する — **絶対最大 6 V**
- **NEVER** veto 回路の pulldown 抵抗を省略する — 起動中に消灯する事故になる
- **NEVER** 未確定の寸法・型番で確定させない。§7 は必ずユーザーに確認する
- **ALWAYS** 親リポジトリの doc を変更する前にユーザー承認を取る (親 `CLAUDE.md` §8.4)
- **ALWAYS** 全実装部品に LCSC 番号を設定する。ただし**秋月調達品は手はんだ前提で例外扱い**とし、
  その旨を BOM に明記する ([`docs/05`](05-jlcpcb-fab.md))
- **ALWAYS** ドキュメントに絶対パスを書かない (作業機が変わる前提)
</hard_rules>
