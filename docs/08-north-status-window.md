## 1. Goal / 何を作るか

<goal>
球体 (Isolation Sphere V2) の**北極キャップを、電源状態と充電状態が見える「ステータス窓」に作り替える。**

解決する問題は 2 つ:

1. **電源 ON/OFF が分からない** — 磁石をかざして電源を入れても、コントローラ (M5 AtomS 系) の起動に時間がかかるため、
   その間ユーザーは ON なのか OFF なのか判断できない。**ファームウェアに依存しないハードウェア表示**が必要。
2. **既存の指示 LED が見えない** — [`docs/06`](06-power-switch.md) §3.6.2 の電源 ON LED と
   [`docs/02`](02-ip2326-module.md) §3.5 の充電中 LED は**どちらも電源基板上 = 球体コアの中**にあり、
   外殻に埋まって視認できない。**北極キャップへ移設する。**

加えて **「再生が始まったら消灯する」** — コントローラがコンテンツ再生を開始したら、
ステータス窓を消して演出の邪魔をしない。これは ESP32 からの veto 線 1 本で実現する (§4.3)。
</goal>

## 4. Electrical specification / 電気仕様

### 4.1 System context (前提となる電源アーキテクチャ)

```
2S LiPo ──> [XR-2S-30A BMS (基板外)] ──> PACK_P (6.0-8.4V)
                                            │
                        ┌───────────────────┼──────────────────┐
                        │                   │                  │
                   [IP2326 充電]      [HT7333-1 LDO]     [MP1584 降圧]
                   CHG_IN=南極磁気端子   3.3V 常時オン        EN 制御で ON/OFF
                        │                   │                  │
                    pin6=充電LED        ┌───┴───┐            V5V (5V/3A)
                        │               │       │                │
                        │          ホール素子  [D-FF]            └─> AtomS + LED 800
                        │           (北極)   Q=電源状態
                        │                       │
                        └──────────────> 北極ステータス窓 <───────┘
```

**重要**: 3.3 V LDO は**常時オン**。だから電源 OFF 中でもホール素子と D-FF が生きていて、
かざした瞬間に反応できる。この構造が本 doc の前提。詳細は [`docs/06`](06-power-switch.md)。

### 4.2 北極 pillar を通る配線 — 6 本

| # | 信号名 | 方向 | 内容 |
| --- | --- | --- | --- |
| 1 | `V3P3` | 基板 → 北極 | 常時オン 3.3 V。**ホール素子専用** (veto の影響を受けてはならない) |
| 2 | `GND` | — | 共通グランド |
| 3 | `HALL_OUT` | 北極 → 基板 | ホール素子出力 (磁石検出) → D-FF の CLK |
| 4 | `LED_VCC` | 基板 → 北極 | **veto でゲートされた LED 用アノード共通レール** (§4.3)。2 灯を一括で消す |
| 5 | `STAT_PWR_K` | 北極 → 基板 | 電源 ON LED のカソード側戻り (基板側で Q によりスイッチ) |
| 6 | `STAT_CHG_K` | 北極 → 基板 | 充電 LED のカソード側戻り → IP2326 pin 6 |

- **線材: AWG30 級の細線 × 6**。AWG30 は被覆込み Φ0.5 mm 級なので Φ3 mm (断面 7 mm²) 通路に余裕で収まる
- ⚠️ **`V3P3` と `LED_VCC` を共用してはならない** — 共用するとホール素子が veto 中に停止し、
  再生中に磁石をかざしても電源が切れなくなる
- **`HALL_OUT` は必ずツイストする** — 球内に WS2812 データ 5 本が走っており、
  40〜50 mm の引き回しはノイズを拾う。ホール出力はドライブされた低インピーダンスなので
  リードスイッチ (高インピーダンスのプルアップノード) よりは有利だが、対策は入れる
- 基板側に **RC ローパス** (例 1 kΩ + 1 nF) を入れる

### 4.3 インジケータの駆動 + 再生開始で 2 灯とも消灯する仕組み (veto)

**電流制限抵抗と LED はキャリア基板に、スイッチング素子は電源基板に置く。**

**設計方針: veto は「LED 用アノードレール `LED_VCC` を 1 個の素子で切る」。**
こうすれば **電源 ON LED と充電 LED の 2 灯を 1 箇所で一括消灯**でき、
IP2326 pin 6 の駆動経路に一切手を入れずに済む (pin 6 の駆動形式が §7 Q2 で未確定なため重要)。

```text
                    [電源基板]                          │      [キャリア基板 = 北極]
                                                        │
  V3P3 ──┬─────────────────────────────────────────────┼──> ホール素子 (veto の影響を受けない)
         │                                              │
         ├── Q_RAIL.source (P-MOS)                      │
         │      │  gate ──┬── R 100k ── GND  (default ON = 点灯)
         │      │         └── R 10k ──── VETO 信号 (H で OFF = 消灯)
         │      │                                       │
         │   Q_RAIL.drain ── LED_VCC ══════════════════>┼──┬── R 680Ω ── LED_PWR ──┐
         │                                              │  │  (Vf 2.0V → 2.0mA)    │
         │                                              │  └── R xxxΩ ── LED_CHG ──┼─┐
         │                                              │     (値は §7 Q2 で確定)  │ │
         │   Q_LED.drain <════ STAT_PWR_K ══════════════┼─────────────────────────-┘ │
         │      │ (2N7002)                              │                            │
         │     GND                                      │                            │
         │      gate ── R 10k ── Q (D-FF 出力)          │                            │
         │                                              │                            │
         └── IP2326 pin 6 <════ STAT_CHG_K ═════════════┼────────────────────────────┘
```

**`VETO` 信号の作り方は 3 案あり (下記)。上の骨格はどの案でも共通。**

⚠️ **`Q_RAIL` の gate は R 100k で GND へプルダウンする (default = 点灯)。**
これが boot-safe を保証する — AtomS3R が起動中で veto を driveできない間、
LED レールは生きたままになる。**このプルダウンは省略不可。**

#### ⚠️ 制約: M5 AtomS3R は GPIO を使い切っている (2026-08-11)

当初案の「ESP32 の GPIO 1 本で veto」は**使えない**。代替 3 案を比較する。

| | **案 A: WS2812 データ活動検出** | 案 B: I2C GPIO エキスパンダ | 案 C: RC タイムアウト |
| --- | --- | --- | --- |
| GPIO 消費 | **0** | **0** (既存 I2C バスに相乗り) | **0** |
| firmware 変更 | **不要** | 必要 (1 bit 書くだけ) | **不要** |
| 追加部品 | 6 点 (すべて既存 BOM の型番) | IC 1 個 + 受動数点 + アドレス管理 | **4 点** |
| 消灯タイミング | **WS2812 へフレームが流れ始めた瞬間** | firmware が決めた任意の時点 | 電源 ON から固定時間後 |
| 意味的な正しさ | **「再生を始めたら」とほぼ一致** | 最も正確 (任意の条件で制御可) | 近似 (起動が遅れると先に消える) |
| リスク | データ線への負荷 (要高インピーダンス設計) | I2C バスが GPIO として使われていると成立しない | 起動時間のばらつきを吸収できない |

**推奨は案 A。** GPIO も I2C も firmware も使わず、しかも「再生が始まった」という
意味そのものを直接検出できる。

#### 案 A の回路 (WS2812 データ活動検出) — **フォールバック**

⚠️ **2026-08-11 に方針変更: I2C 端子が基板上で使用可能と判明したため、`VETO` は
§4.4 案 1 (I2C GPIO エキスパンダ) から取る。** 案 A は **I2C が使えないと分かった場合の
代替**として残す (定数まで算出済みなので即着手できる)。

Grove ポートは BNO055 が使用中だが、**I2C はバスなので別アドレスのデバイスを追加できる**
(§4.4)。案 A を使うのは、アドレス衝突・バス速度・実装スペースなどで
エキスパンダが載らないと判明した場合に限る。

##### ① 入力信号の実測前提 (WS2812 のタイミングから計算)

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| ビット周期 | **1.25 µs** (800 kbps) | WS2812 プロトコル |
| **High の最大継続時間** | **T1H ≈ 0.8 µs** (公差込みで 1 µs 未満) | 「持続 High は通常発生しない」ことの根拠 |
| バースト内のデューティ | **28%** (全ビット 0) 〜 **60%** (全ビット 1) | T0H 0.4 / T1H 0.8 ÷ 1.25 |
| **1 フレームの送出時間** | **4.8 ms** | 160 LED × 24 bit × 1.25 µs。**5 本は並列駆動なので 1 本ぶんの時間** |
| フレーム間隔 (30 fps 想定) | 33.3 ms | — |
| **「データあり」の実効デューティ** | **4.0%** (全 0) 〜 **8.6%** (全 1) | 4.8 ms × バースト内デューティ ÷ 33.3 ms |

**設計は最悪条件 (実効デューティ 4.0% = 全ビット 0 = 全消灯フレーム) で成立させる。**

##### ② 回路

```text
  WS2812 DIN ──[R1 100k]──┬──[D1 1N4148W]──┬── V_ACT ──[R3 1M]── Q_ACT.base
   (3.3V, 800kbps)        │                │                     (MMBT3904 / C20526)
                          │             C1 100nF                        │
                       ピーク電流         │                       Q_ACT.collector
                       33 µA のみ       R2 4.7M                        │
                       = 信号品質に       │                        VETO ノード
                       影響しない        GND
```

##### ③ 定数の根拠

| 項目 | 式 / 値 |
| --- | --- |
| 充電の実効時定数 | `τc = R1·C1 / 実効デューティ` = 10 ms / 0.040 = **250 ms** |
| 放電の時定数 | `τd = R2·C1` = 4.7 MΩ × 100 nF = **470 ms** |
| `V_ACT` の平衡電圧 | `(3.3 − Vf) × τd/(τd+τc)` = 2.7 × 470/720 = **1.76 V** |
| しきい値 | **NPN の Vbe = 0.6 V** |
| **余裕** | 1.76 / 0.6 = **2.9 倍** ✓ |
| 消灯までの時間 | 数フレーム (≈100 ms 以内) |
| **再点灯までの時間** | `τd × ln(1.76/0.6)` = **約 0.5 s** |

- **しきい値に NPN の Vbe (0.6 V) を使う。** MOSFET の Vth (2N7002 で 1.0〜2.5 V の 2.5 倍ばらつき)
  に依存させない — [`docs/06`](06-power-switch.md) §3.6.4 で採った設計方針と同じ
- `R3 = 1 MΩ` にして **`V_ACT` からの引き出しを 1.2 µA に抑える**。
  こうすればチャージポンプの供給能力 (1 フレームあたり 40 nC 級) で余裕をもって支えられる。
  ⚠️ `R3` を 10 kΩ にすると 120 µA を引いてポンプが追従できず**平衡電圧が崩壊する**
- **`R1 = 100 kΩ` でデータ線への負荷はピーク 33 µA のみ。** ESP32 GPIO の駆動能力
  (20〜40 mA) に対して 0.1% 以下で、信号品質に影響しない
- **部品はすべて既存 BOM の型番を流用できる**: MMBT3904 = `C20526` /
  1N4148W = MP1584 の BST ダイオード `D3` と同型 / 抵抗・コンデンサは 0603 の既存品番
- **オフ時電流は 0** — `V_ACT` が 0 V なので `R2` にも `R3` にも電流が流れない

##### ④ VETO の極性と出力段 — **IP2326 pin 6 の駆動形式で 2 通りに分かれる (§7 Q2)**

`Q_ACT` (NPN) は **GND へ引く**ことしかできない。一方 boot-safe の要件から
**「detector 非活性 = 点灯」がデフォルト**でなければならない。この組み合わせで topology が決まる。

| pin 6 が | LED の共通側 | veto 素子 | 極性の整合 | 追加部品 |
| --- | --- | --- | --- | --- |
| **ソース (吐き出し)** | **共通カソード → GND** | **N-MOS 1 個** (ゲートを V3P3 へ 100 kΩ でプルアップ = default ON) | **`Q_ACT` がゲートを引き下げて消灯 — 直結で成立** ✓ | N-MOS + R 100 kΩ = **2 点** |
| **シンク (吸い込み)** | **共通アノード `LED_VCC`** | **P-MOS** (§4.3 の骨格) | `Q_ACT` では P-MOS ゲートを V3P3 まで**持ち上げられない** → **PNP 1 石の反転段が必要** | P-MOS + PNP + R×3 = **5 点** |

**pin 6 がソースなら回路が 3 点少なく済む。** §7 Q2 を先に確定させること。

##### ⑤ 実装上の注意

- **タップするのは 5 本のうち 1 本。** 常に駆動される系統を選ぶ
  (一部の系統だけ止める実装があると誤検出する)
- **タップ線は 50 mm 以下に抑える。** 800 kbps に対する容量負荷は
  50 mm ≈ 5 pF 程度で問題にならないが、長くする場合は `R1` をタップ点側に置く
- **電源基板に WS2812 データ線のタップ入力が 1 本増える** — コネクタ 1 ピンを確保する
  ([`docs/01`](01-legacy-analysis.md) §4 のコネクタ構成に反映)
- **この同じタップは将来 `PWR_OFF` にも再利用できる** — WS2812 は High が
  0.8 µs しか続かないので、**数十 ms の持続 High は通常動作では絶対に起きない**一意な合図になる。
  ただし `V_ACT` は持続 High でも飽和するため、**判別には 2 段目のしきい値が必要** (§4.4 案 2)

⚠️ **案 A の意味論に注意**: 検出しているのは「**firmware が WS2812 フレームを送出している**」で、
「コンテンツを再生している」ではない。**firmware が待機中も黒フレームを流し続ける実装だと、
待機状態でも消灯する。** ファームウェアの挙動を確認して判断すること (§7 V3)。

#### 動作表 (案 A の場合)

| 状態 | Q | VETO | 電源 ON LED | 充電 LED |
| --- | --- | --- | --- | --- |
| 電源 OFF・充電なし | L | L | 消灯 | 消灯 |
| **電源 OFF で充電中** | L | L | 消灯 | **点灯** ← 消灯のまま充電できることの可視化 |
| **かざした瞬間 〜 AtomS 起動中** | **H** | **L** | **点灯** ← 解決したい問題 | 充電中なら点灯 |
| **動画再生中** | H | **H** | **消灯** | **消灯** ← 2 灯とも消える (2026-08-11 確定) |
| 再生停止 / 送出が 100 ms 以上途切れた | H | L | 点灯 | 充電中なら点灯 |

**boot-safe が最重要要件**: `Q_RAIL.gate` の pulldown が無いと `VETO` ノードが不定電位になり、
起動中に消灯する事故が起きる。**どの案を選んでも pulldown は省略不可。**

### 4.4 ESP32 インターフェースと GPIO 拡張

<constraint>
**M5 AtomS3R は GPIO を使い切っており、veto 線も電源オフ線も割り当てられない (2026-08-11)。**
必要な信号は 2 本:

| 信号 | 方向 | 用途 | 現在の扱い |
| --- | --- | --- | --- |
| `VETO` | AtomS → 基板 | 再生開始でステータス窓を消灯 (§4.3) | 本 doc で新設 |
| `PWR_OFF` | AtomS → 基板 | ソフト電源断 (D-FF の CLR を引く) | **2026-08-11 にペンディング解除 → 実装する** ([`docs/06`](06-power-switch.md) §1 の「パッド予約のみ」を改訂) |

**GPIO は 1 本も空いていないが、I2C 端子が基板上に実装済みで使用可能** (2026-08-11 ユーザー確認)。
I2C は**バス**なので、Grove の BNO055 と同居しながらデバイスを追加でき、**GPIO を消費しない。**
</constraint>

#### 拡張方法 3 案

##### ① ⚠️ 落とし穴 1: 電源ドメインの選択

| 電源 | 利点 | 致命的な問題 |
| --- | --- | --- |
| **常時オン 3.3 V (`V3P3`)** | 配線が単純 | **前回セッションの veto 状態が残る。** 再生中に電源を切ると veto=有効のまま保持され、**次回起動時にステータス窓が点かない** — 本 doc が解決しようとしている問題そのものが再発する |
| **電源 ON 中の系 (推奨)** | **毎回リセットされるので状態が残らない** ✓ / **オフ時電流に寄与しない** ✓ | 未通電時のリーク経路に注意 (下記 ②) |

**推奨: AtomS3R の 3V3 出力から給電する。** I2C バスの論理レベルも AtomS3R の 3.3 V と
自動的に一致するので、レベル変換が不要になる (§7 V8 で 3V3 ピンの供給能力を確認)。

##### ② ⚠️ 落とし穴 2: 未通電時のリークと power-up 出力状態

エキスパンダを ON ドメインで動かすと、**電源 OFF 中はエキスパンダが未通電**になる。
このとき信号線を常時オン側のプルアップで保持すると、
**プルアップ電流が未通電 IC の ESD ダイオード経由で VDD へ流れ込む** — 100 kΩ × 2 本で
**66 µA**、オフ時電流の予算 50 µA を単独で超える。

**対策: エキスパンダの出力を直接つながず、小信号 N-MOS 1 石ずつで受ける。**

```text
   [ON ドメイン]                    │        [常時オン ドメイン]
                                    │
  エキスパンダ Px ──┬── R 10k ──────┼── Q_x.gate      (Q_x = 2N7002)
                    │               │      │
                  R 100k            │   Q_x.drain ──> 信号ノード
                  (pulldown)        │      │          (VETO / CLR)
                    │               │     GND         ← R 100k で V3P3 へプルアップ
                   GND              │
```

- **未通電時**: `Px` が高インピーダンス → `R 100k` の pulldown が `Q_x` のゲートを GND に固定
  → `Q_x` OFF → **リーク経路なし** ✓ かつ信号ノードはプルアップで H = 非アサート ✓
- **極性**: エキスパンダが **H を出すとアサート** (`Q_x` が信号を GND へ引く) になる
- **したがってエキスパンダは「power-up 時に出力が H にならない」品種でなければならない。**
  **`PCA9536` は power-up 時に全ピンが入力 (高インピーダンス) になる**ので条件を満たす。
  ⚠️ **`PCF8574` は power-up 時に出力が H** になるため、この topology では
  **起動と同時に電源が切れる**。**PCF8574 を採用してはならない** (§7 V7 で最終確認)
- pulldown があるので **boot-safe も同時に満たす** — firmware が走る前は両信号とも非アサート
  = ステータス窓は点灯、電源は入ったまま ✓

##### ③ `PWR_OFF` の動作シーケンス

1. firmware が `P1` を H にする → `Q_1` が D-FF の `CLR` を GND へ引く
2. D-FF がクリア → `Q` = L → MP1584 の EN が L → 5V 崩壊 → **電源 OFF**
3. 5V が消える → AtomS3R とエキスパンダが未通電 → `Q_1` OFF → `CLR` はプルアップで解放
4. **D-FF は常時オン 3.3 V で生きており `Q` = L を保持** → 再投入ループは起きない ✓

| --- | --- | --- |
| I2C GPIO エキスパンダ (PCA9536 系) | 1 | 電源基板 |
| パスコン 100 nF | 1 | 電源基板 |
| N-MOS 2N7002 (`C8545`) | 2 | 電源基板 |
| 抵抗 (ゲート直列 10 k ×2 / pulldown 100 k ×2 / プルアップ 100 k ×2) | 6 | 電源基板 |

- **AtomS3R との接続線: SDA / SCL / 3V3 / GND = 4 本** (既存 I2C 端子を流用)
- I2C バスのプルアップ抵抗が基板側にあるか AtomS3R 側にあるかを確認 (§7 V9)

### 4.4b ★採用: PCA9632 (I2C 4ch LED ドライバ) — 2026-08-11

**GPIO エキスパンダではなく「I2C LED ドライバ」を使うのが本件には最適。**
ユーザー提示: [Switch Science PCA9632DP1 I2C 4ch LED ドライバ基板 ¥611 / 在庫 88](https://www.switch-science.com/products/2378)

#### なぜエキスパンダより良いのか — 4 点

| 特性 | 本件での意味 |
| --- | --- |
| **出力がオープンドレイン (シンク 25 mA/ch)** | 必要な操作は「プルアップされたノードを GND へ引く」だけ。**極性が完全に一致し、N-MOS のバッファが不要**になる (エキスパンダ案で必要だった 2 石 + 抵抗 4 本が消える) |
| **LED ドライバなので power-up 時は消灯 = 出力オフ** | **`VETO` も `PWR_OFF` も power-up 時に非アサート** → **boot-safe が無条件で成立**。`PCF8574` の「power-up で出力 H → 起動と同時に電源が切れる」危険が原理的に発生しない |

| ch | 用途 | 接続 |
| --- | --- | --- |
| ch0 | **`VETO`** | LED アノードレールの N-MOS ゲート (V3P3 へ 1 MΩ プルアップ = default ON = 点灯) を**シンクして消灯** |
| ch1 | **`PWR_OFF`** | D-FF の **CLR** (V3P3 へ 470 kΩ プルアップ) を**シンクして電源 OFF** |
| ch2, ch3 | 予備 | 将来の 3 灯目 / RGB / `PWR_STATE` など |

- 電源 ON 表示の「かざした瞬間に点灯」は従来どおり **D-FF の `Q` からハードウェアで駆動**する。
  PCA9632 は**それを消す側**にだけ関与する — これで firmware 起動前の点灯が保証される

#### ⚠️ 電源ドメインと未通電時リーク (エキスパンダ案と同じ論点)

- **PCA9632 は「電源 ON 中の系」(AtomS3R の 3V3) から給電する。**
  常時オンにすると**前回の veto 状態がレジスタに残り、次回起動時にステータス窓が点かない**
  (PCA9632 はソフトウェアリセットのみでリセットピンが無いため、電源で落とすのが唯一の確実な手段)
- 未通電時、常時オン側のプルアップ電流が **ESD ダイオード経由で流れ込む**。
  **プルアップを大きくして抑える**:

| ノード | プルアップ | リーク | 備考 |
| --- | --- | --- | --- |
| LED レール N-MOS ゲート | **1 MΩ** | 3.3 µA | ゲートは高インピーダンスなので 1 MΩ で問題ない |
| D-FF の `CLR` | **470 kΩ** | 7.0 µA | LVC の入力リーク ±1 µA max を考慮。1 MΩ では H レベルの余裕が薄い (§7 V10) |
| **合計** | — | **約 10 µA** | オフ時合計 **約 28 µA typ** → **目標 ≤50 µA を満たす** ✓ |

### 4.4a フォールバック: WS2812 データ線 + GPIO06 から取る

⚠️ **PCA9632 (§4.4b) が使えないと分かった場合の代替。** 以下は設計・定数まで算出済みなので即着手できる。

**`VETO` と `PWR_OFF` を GPIO を消費せずに作る。**

| 信号 | 取得元 | 検出方法 | 原理 |
| --- | --- | --- | --- |
| `VETO` | **WS2812 データ線 (0 ピン)** | **活動検出** (§4.3 案 A) | フレームが流れている = 再生中 |
| `PWR_OFF` | **GPIO06 (スピーカと共用)** | **「Low が来ないこと」の検出** (下記) | **音声は AC なので 100 ms の DC High を保つことは絶対にない** |

#### M5 AtomS3R の外部ピンは 6 本しかない (2026-08-11 ユーザー確認)

| ピン | 用途 | 空き |
| --- | --- | --- |
| GPIO01〜05 | **WS2812 5 ストリップの制御** | ✗ (親プロジェクトの必須要件) |
| **GPIO06** | **スピーカ** | **共用の可否が論点 (下記)** |
| 内部の他ピン | 製品として線が出ていない (ESP32-S3 には存在する) | 実質不可 — **モジュール上のパッドへ手はんだする改造が必要。極小モジュールでは現実的でない** |

#### ✅ GPIO06 は **`PWR_OFF` に限って共用できる** — スピーカを維持したまま

**信号の性質が違うので、共用の可否は信号ごとに分かれる。**

| 信号 | 性質 | GPIO06 共用 |
| --- | --- | --- |
| `VETO` | **再生中ずっと保持する静的レベル** | **✗ 不可** — 音を鳴らしている間レベルが暴れる。時間多重が成立しない |
| **`PWR_OFF`** | **意図した瞬間だけの一過性の操作** | **✅ 可能** — 下記の理由で音声と原理的に弁別できる |

**弁別できる理由: 音声信号は AC であり、100 ms のあいだ DC High を保つことは絶対にない。**
したがって「持続 High 検出」(下記の `PWR_OFF` 検出回路) は、
**スピーカが鳴っていても誤発火しない。**

- firmware は電源を切りたいとき **GPIO06 を 100 ms 以上 High に保持するだけ**
- **スピーカ機能はそのまま残せる** — 音声出力と電源オフ指示が同じ線で共存する
- ⚠️ **タップ位置はアンプ/ドライバの前 (GPIO 側)** にする。3.3 V ロジックレベルを直接見る
- ⚠️ **スピーカを直結駆動している場合、100 ms の DC High はコイルに直流を流す。**
  「プツッ」という音が出る (電源オフの合図としては実用上むしろ都合が良いが、
  素子保護の観点で直流耐性を確認する) → §7 V12

**これにより WS2812 データ線に触るのは `VETO` の活動検出だけになる。**
活動検出は「データが無い = veto しない = 点灯」という安全側に倒れる回路なので、
**LED データ線に critical な依存を作らずに済む** — 当初 `PWR_OFF` も WS2812 から
取ろうとしていた案より安全。

#### `PWR_OFF` の検出回路 — GPIO06 で「Low が来ないこと」を見る

振幅ではなく **「一定時間 Low が現れないこと」** で弁別する。
音声信号は AC なので必ず Low に戻る → **原理的に誤動作しない。**

```text
  V3P3 ──[R4 1M]──┬── V_OFF ──[R5 220k]──┬── Q_OFF.base (MMBT3904)
                  │                       │
                C2 100nF              [R6 100k]
                  │                       │
                 GND                     GND
                  │
  GPIO06 ─────────┴──[D2 1N4148W]  (アノード = V_OFF 側 / カソード = GPIO06 側)
   (アンプ前の
    ロジック側)  │
             [R7 10k] ← ⚠️ プルダウン (必須・下記)
                │
               GND
```

| 状態 | GPIO06 | `V_OFF` | 判定 |
| --- | --- | --- | --- |
| **音声出力中** | AC で必ず Low に戻る | **D2 が毎周期 放電 → 0.6 V に固定** | 非アサート ✓ |
| 無音 / 待機 / 起動中 | **Low で静止** (プルダウンで確定) | D2 が導通し続け 0.6 V | 非アサート ✓ |
| **firmware が意図的に High 保持** | High 継続 | **D2 が切れて `R4·C2` で充電** | **しきい値到達で `PWR_OFF`** |

- 充電時定数 `R4·C2` = 1 MΩ × 100 nF = **100 ms**
- 分圧 `R5:R6 = 220k:100k` によりトリガは `V_OFF ≈ 1.9 V` (NPN の Vbe 0.6 V に対応)
- 到達時間 = `100 ms × ln((3.3−0.6)/(3.3−1.9))` = **約 66 ms**
  → **firmware は該当ピンを 100 ms 以上 High に保持するだけでよい**
- ⚠️ **`R7 10 kΩ` のデータ線プルダウンは必須。** ESP32 の GPIO は起動中 High-Z になりうる。
  プルダウンが無いと線が浮いて **起動中に `PWR_OFF` が誤発火し、電源が落ちる**。
  WS2812 の DIN を確定させる意味でも定石
- しきい値に **NPN の Vbe (0.6 V)** を使う方針は §4.3 と同じ
- **オフ時電流**: 電源 OFF 中は `V3P3` から `R4` 経由で `C2` が充電され、
  `D2` がデータ線 (プルダウンで Low) へ流す → **3.3 V / 1 MΩ ≈ 3.3 µA が常時流れる**。
  ⚠️ これは無視できないので、**`R4` を `V3P3` ではなく `LED_VCC` か
  「電源 ON 中の系」から取ることを検討する** (§7 V11)

#### 部品まとめ (WS2812 方式・2 信号)

| 用途 | 部品 | 数 |
| --- | --- | --- |
| 共通 | データ線プルダウン `R7` | 1 |
| `VETO` 活動検出 | `R1` `D1` `C1` `R2` `R3` + NPN | 6 |
| `PWR_OFF` 検出 | `R4` `C2` `D2` `R5` `R6` + NPN | 6 |
| 出力段 | §4.3 ④ の topology (pin 6 の駆動形式次第で 2〜5 点) | 2〜5 |

**合計 15〜18 点。** I2C エキスパンダ案 (10 点) より多いが、**GPIO も I2C も消費せず、
小型パッケージの入手性に依存しない**。すべて 0603 / SOT-23 の既存 BOM 型番で構成できる。

#### 案 2 の詳細 (参考・上記 `PWR_OFF` 検出の原型)

WS2812 のプロトコルでは **High が最大 ~0.9 µs (T1H) しか続かない**。
したがって **数十 ms continuous High は通常動作では絶対に発生しない** → 一意な合図として使える。

- firmware は該当ピンを `HIGH` にして 100 ms 保持するだけ
- 基板側は RC ローパス + NPN で「持続 High」を検出 → `PWR_OFF` を生成
- ⚠️ **通常のフレーム送出との判別に設計余裕が必要**: WS2812 のビット列はデューティ
  33〜66% なので、RC の整定値が全ビット 1 のときと持続 High で近づく。
  **しきい値の余裕を計算で裏取りすること**。余裕が取れない場合は案 1 に戻る

### 4.5 充電中 LED

- IP2326 **pin 6** が駆動 (充電中点灯 / 満充電消灯 / 異常点滅を IC が自動判定)
- アノードは **`LED_VCC`** から取る。`LED_VCC` は常時オンの `V3P3` を veto でゲートしたものなので:
  - **電源 OFF 中の充電でも点灯する** ✓ (「消灯のまま充電できる」ことがユーザーに見える)
  - **動画再生中は電源 ON LED と一緒に消灯する** ✓ (2026-08-11 確定)
- 直列抵抗はキャリア基板側に置く。値は pin 6 の駆動形式が確定してから決める (§7 Q2)
- ⚠️ **異常表示は別 LED を足さなくてよい** — IP2326 が**異常時に点滅**させるので、
  この 1 灯が「充電中 / 満充電 / 異常」の 3 状態を表現する

### 5.1 北極キャップ — ⚠️ 窓と競合する

- 現行: 黒 PETG の**純粋装飾蓋**、pillar へ**スナップ留め** (中央ねじなし)

| 案 | 内容 |
| --- | --- |
| **a. キャップに開口を設ける** | 五角形穴と位置を合わせた窓を開ける。黒の意匠を保てる |

#### ★ダイオード OR — 線を 6 本に保ったままスイッチを足す (案 2・2026-08-11 確定)

```text
                     C2 100nF ← U1 の VDD パスコン (+3V3—GND 間・並列)
                        │
   +3V3 ────────────────┴── U1.2 (VDD)
                             │
   U1.3 (OUT / CMOS) ──[D3]──┬──────────── OUT  ──> 電源基板へ
                      A    K │
                             │
       +3V3 ──[R3 1k]── SW1 ─┤   ← 突くと H に引き上げる
                             │
                             ├──[R4 100k]── GND      ← プルダウン
                             │
                          [C1 100nF]                 ← τ = 10ms
                             │
                            GND
```

| 状態 | `OUT` | 判定 |
| --- | --- | --- |
| 磁石なし・SW 押さず | ホールが L → **D3 が逆バイアスで遮断** → `R4` が 0 V に固定 | L (何も起きない) |
| **磁石をかざす** | ホールが H → D3 導通 → **3.3 − 0.6 = 2.7 V** | **H** (VIH 2.0 V に対し余裕) → トグル |
| **SW1 を突く** | `+3V3` → `R3` → ノード。`R4` は 100 kΩ なので **3.27 V**。**このとき D3 は逆バイアスでホールの L 出力を遮断** | **H** → トグル |

**`D3` が要点。** ホール素子は CMOS 出力なので、そのまま並列にすると
スイッチが H に引こうとしても**ホールの L 側ドライバ (Ron 約 50 Ω) が勝ってしまう**。
`D3` を入れると**ホールは「上げる」ことしかできなくなり**、スイッチと衝突しない。

⚠️ **`C2` は `+3V3` と `GND` の間に並列**に入れる。**`+3V3` → `C2` → `U1.VDD` と
直列にしてはならない** — `U1` が無通電になり回路全体が死ぬ (作図レビューで実際に出た誤り)。

- **SW1 は磁石と完全に等価なトグル**になる (強制 ON ではない) → 磁石紛失時の完全な代替
- **デバウンスは `R4·C1` = 10 ms が兼務**。Schmitt (`74LVC1G17`) は任意に遅い遷移を受け付けるので問題ない
- **電源基板の変更は不要** — `R1` DNP / Schmitt = バッファ という確定事項がそのまま生きる
- オフ時電流への影響 **0** — ホールが L のとき `R4` に電流は流れない

#### SW1 を実装しない / 配線しない場合 — **問題なく動きます**

**`D3` / `R4` / `C1` の 3 点だけで回路は完結している**ので、`SW1` は**任意実装 (オプション)** にできる。

| 構成 | `OUT` の挙動 |
| --- | --- |
| SW1 あり | 磁石 **または** 突きでトグル |
| **SW1 未実装 / 未配線** | **磁石のみでトグル。他は一切変化なし** ✓ |

`SW1` の端子が開放でも、ノードは `R4` で確実に 0 V に固定されるため**浮きません**。
したがって **「とりあえずフットプリントと配線を入れておき、実装は後で決める」**という運用が安全にできる。
**配線しておくコストはゼロ**なので、パターンは引いておくことを推奨する。

⚠️ **緑・青は使えない。** InGaN 系は **Vf = 3.6 V** で、`LED_VCC` = 3.3 V では
順方向電圧に届かず点灯しない。**赤 / 橙 / 黄 (Vf ≈ 2.0 V) から選ぶ。**

#### S-5716A のピン配置 (EasyEDA ライブラリの検証済みシンボルから確定)

| pin | 名前 | 接続 |
| --- | --- | --- |
| **1** | **VSS** | `GND` |
| **2** | **VDD** | **`V3P3`** (常時オン。2.7〜5.5 V の範囲内 ✓) |
| **3** | **OUT** | **`HALL_OUT`** → pillar 経由で電源基板へ |

**プルアップとノイズフィルタは北極側に置かない** — 電源基板側の `R1 100 kΩ`
(OD 出力なら実装 / CMOS 出力なら DNP) と `R2 1 kΩ + C5 1 nF` が担当する
([`docs/06`](06-power-switch.md) §4.9)。**北極基板は素子を出すだけ。**

#### 電流制限抵抗の計算

`LED_VCC` = 3.3 V、Vf = 2.0 V、スイッチの Vds(on) ≈ 0.05 V として:

```
R = (3.3 − 2.0 − 0.05) / 2 mA = 625 Ω  →  E24 で 680 Ω  →  実効 1.84 mA
```

| 系統 | 電流 | 制約の確認 |
| --- | --- | --- |
| `D1` (電源 ON) | 1.84 mA | 電源基板の N-MOS がシンク。余裕十分 |
| `D2` (充電) | 1.84 mA | **IP2326 pin 6 の最大 5 mA に対し 37%** ✓ |

⚠️ **[`docs/02`](02-ip2326-module.md) §3.5 の「LED + 100 Ω」をそのまま使ってはならない。**
`LED_VCC` = 3.3 V で 100 Ω だと **13 mA** になり、**pin 6 の 5 mA 定格を超える**。
標準回路は別の電源電圧を前提にした値なので、**本設計は 680 Ω を使う。**

#### 電源 OFF 中の消費

`LED_VCC` は常時オンだが、**両 LED のカソード側が開いているため電流は流れない**:

| 状態 | `D1` | `D2` | `V3P3` からの消費 |
| --- | --- | --- | --- |
| 電源 OFF・充電なし | N-MOS off (`FF_Q`=0) | pin 6 シンクなし | **0 mA** ✓ |
| 電源 OFF・充電中 | 消灯 | **1.84 mA** | 充電器が給電中なので問題なし |
| 電源 ON | 1.84 mA | 充電中なら 1.84 mA | システムが 0.6 A 以上引くので無視できる |

#### コネクタの分割 (2026-08-11 確定)

**電源 2 極 + 信号 4 極の 2 コネクタに分ける。** 南極の送信側基板が `J2`(2.00 mm) / `J3`(2.54 mm) と
ピッチ違いで 2 個持っているのと同じ流儀。

| コネクタ | 極数 | 信号 | 備考 |
| --- | --- | --- | --- |
| **CN1 (電源)** | **2** | `V3P3` / `GND` | ホール素子の電源。**常時オン系** |
| **CN2 (信号)** | **4** | `HALL_OUT` / `LED_VCC` / `STAT_PWR_K` / `STAT_CHG_K` | `LED_VCC` は LED 2 灯ぶんで **3.7 mA** しか流れないので信号側で問題ない |

- 電源系と信号系を分けることで、**組立時の挿し間違いが物理的に起きにくくなる**
- ⚠️ **`V3P3` と `LED_VCC` を同じコネクタに入れない** — `LED_VCC` は veto でゲートされた別系統。
  混同すると veto 中にホール素子が止まり、**再生中に磁石で電源を切れなくなる**
- 実装形態 (ピンヘッダか、パッドへ直ハンダか) は §7 Q9。
  **直ハンダにする場合は BOM と position ファイルから除外**する
- KiCad 正本では **`J1` (2P) / `J2` (1×4)** のシンボルで作図済み。**フットプリントは Q9 の決定待ち**

### 5.3 ホール素子の向き

- **磁石は北極の真上 (極軸方向) から近づく**
- ホール素子は**感磁面を極軸に対して垂直**に置く (磁束が素子面を貫くように)
- リードスイッチとは向きの考え方が違うので注意 (リードは長軸方向が高感度だった)

### 5.4 配線経路 — **親プロジェクトへの影響が縮小した**

基板は**内側の pillar 先端**にあり、**五角形穴は LED の窓としてしか使わない**ので、
**配線は穴を通らない。** したがって選択肢は 2 つ:

| 案 | 内容 | 親プロジェクトへの影響 |
| --- | --- | --- |
| **a. pillar の脇を通してコアへ落とす** | 通路を掘らない | **親 `CLAUDE.md` §2.8 の改訂が不要になる** ✓ |
| b. pillar 内部に Φ3 mm 通路を新設 | 南極 pillar と同じ手法。配線が保護され見た目も綺麗 | 親 `CLAUDE.md` §2.8「北極 pillar は配線通路不要」の改訂が必要 |

**a を選べば親プロジェクトの確定仕様を触らずに済む** ([§6](#d7-doc-改訂リスト) の `<impact>` が 1 件減る)。
どちらにするかは §7 Q8。

- どちらでも構造荷重には影響しない — 案 K_new で pillar はクランプ荷重を受けないため
- 6 本は AWG30 級で断面積 約 1.7 mm²。Φ3 mm 通路 (19.6 mm²) なら占有率 9% で余裕

- **V2: 磁石を製品 BOM に載せるか**、ユーザー手持ち運用にするか
- **V3: AtomS の起動時間の実測 + フレーム送出の挙動** — 起動から最初の WS2812 フレームまでの時間。
  **待機中も黒フレームを流し続ける実装かどうか** (§4.3 案 A の意味論に直結)
- **V4: ~~veto に使える GPIO の選定~~** → **GPIO 枯渇のため §4.4 の拡張方式選定に置き換え**。
  型番は **M5 AtomS3R** と判明 (親 `CLAUDE.md` Q2 の解消材料)。
  **5 並列 PIO/RMT 出力が要件**なので、AtomS3R でそれが成立しているかも併せて記録する
- **V7 (最重要): GPIO エキスパンダの品番確定。** 選定条件は 3 つとも必須:
  1. **power-up 時に出力が H にならないこと** (入力/高インピーダンスで起動する)。
     **`PCF8574` は power-up 時に出力 H なので採用不可** — §4.4 ② の topology では
     **起動と同時に電源が切れる**。`PCA9536` は power-up 時に全ピン入力なので条件を満たす見込み
  2. **BNO055 (0x28/0x29) とアドレスが衝突しないこと**
  3. LCSC 在庫とパッケージ (40×40 片面実装に載ること)
- **V8: AtomS3R の `3V3` 出力ピンの有無と供給能力** — エキスパンダ + N-MOS ゲートで
  数百 µA。ここから給電できればレベル変換が不要になる (§4.4 ①)
- **V9: I2C バスのプルアップ抵抗**が電源基板側にあるか AtomS3R 側にあるか。
  二重に付いていないか (バス容量とプルアップ値の確認)
- **V10: D-FF の `CLR` に対する `PWR_OFF` のレベル整合** — LVC の VIL/VIH と
  大きなプルアップでのリーク (LVC 入力リーク ±1 µA max) を確認。§4.4b では 470 kΩ を仮採用
- **V11 (§4.4a を使う場合): `R4` の給電元** — `V3P3` から取ると電源 OFF 中も 3.3 µA 流れる。
  `LED_VCC` か ON ドメインから取れないか検討
- **V12 (§4.4a を使う場合): GPIO06 の 100 ms DC High がスピーカに与える影響** —
  直結駆動ならコイルに直流が流れる。素子の直流耐性と「プツッ」音の許容を確認
- **V14 (NEW): S-5716A の感度ランクと出力オプションの確定。**
  データシートの品名構成表 (2 ページ目以降) が PDF テキスト抽出不能で未確認。確定させたいのは 3 点:
  1. **`P4` の数字と Bop の対応** — 1.8 mT (最高感度) がどのランク番号か。外殻 5 mm を隔てた検出距離に直結
  2. **`P2` = D / S が「Nch オープンドレイン / CMOS」のどちらを指すか** — 電源基板の `R1 100 kΩ` を実装するか DNP にするかが決まる
  3. **`P3` = H / L が「アクティブ H / アクティブ L」のどちらか** — 電源基板の Schmitt を
     `74LVC1G14` (インバータ) か `74LVC1G17` (バッファ) のどちらにするかが決まる
  ⚠️ **いずれも設計は両対応済み**なので回路図は描ける。**部品発注前に確定**させればよい
- **V13 (★最優先・§4.4b): PCA9632 の datasheet 照合と入手性**
  1. **power-up 時に全出力がオフ (LED 消灯) であること** — boot-safe の根拠。**要明文確認**
  2. **消費電流** (動作時 / スリープ時) — ON ドメイン給電なのでオフ時電流には効かないが、
     5V 系の負荷として把握する
  3. **オープンドレイン出力の VOL とシンク能力** — N-MOS ゲートと `CLR` を確実に GND へ引けるか
  4. **LCSC の在庫とパッケージ** (`PCA9632DP1` = TSSOP-8 / DFN 小型品種の有無)
  5. **I2C アドレス 0xC4 (7bit 0x62)** が BNO055 (0x28/0x29) と衝突しないこと ✓ (既に確認済み)
- **V5: pillar 先端の実寸** — キャリア基板の外形が決まる。親 `docs/01-shell-cad.md` を参照
- **V6: HT7333-1 の入力電圧上限**が 2S 8.4 V に対し十分か (LCSC 表記 30 V を datasheet で裏取り)
</open_questions>

## 8. Acceptance criteria / 完了条件

- [ ] **磁石をかざした瞬間** (AtomS の起動を待たず) に北極が点灯する
- [ ] **起動中も点灯し続ける** — AtomS の GPIO が High-Z の間、pulldown で LED が生きている
- [ ] **再生開始で消灯する** — §4.4 で選んだ方式 (I2C エキスパンダ / データ活動検出 / タイムアウト) で消える
- [ ] **veto 経路が AtomS3R の GPIO を 1 本も新規に消費していない** (§4.4 の前提)
- [ ] **もう一度かざすと即座に消灯**し、電源が切れる
- [ ] **firmware から I2C 経由で電源を切れる** (`PWR_OFF`)。切れた後に再投入ループが起きない
- [ ] **電源 OFF 中のリーク経路が無い** — エキスパンダ未通電時にプルアップ電流が
      ESD ダイオードへ流れ込んでいないこと (実測でオフ時電流を確認)
- [ ] **エキスパンダの power-up 出力状態で誤動作しない** — 起動と同時に
      電源が切れたりステータス窓が消えたりしないこと
- [ ] **電池を挿した直後は消灯 (電源 OFF)** — D-FF の POR で保証
- [ ] **電源 OFF のまま充電すると充電 LED だけが点く**
- [ ] **動画再生中は電源 ON LED と充電 LED の両方が消灯する**
- [ ] **ホール素子は veto 中も動作している** — 再生中に磁石をかざして電源を切れること
      (`V3P3` と `LED_VCC` を共用していないことの確認)
- [ ] **南極の充電マグネットを着脱してもホール素子が誤反応しない**
- [ ] オフ時のシステム合計電流が **≤50 µA** (設計見込み: LDO 2.5 + ホール 1.6〜4.0 + D-FF ~1 + MP1584 12 + IP2326 0.7 ≈ **18〜21 µA typ**)
- [ ] **北極キャップを外しても配線を触らずに済む** (素子は pillar 側)
- [ ] **接着剤を 1 箇所も使っていない**

## 9. Hard rules / 厳守事項

<hard_rules>
- **NEVER** 接着剤・瞬間接着剤・エポキシで固定する (親プロジェクトの全損事故履歴)
- **NEVER** 連続動作型のホール IC (mA 級) を使う — オフ電流予算 50 µA を 100 倍超える
- **NEVER** ホールラッチ (bipolar latch) を使う — 磁石を裏返す操作が必要になり UX が成立しない
- **NEVER** MP1584 の EN を 2S レール (6.0〜8.4 V) に接続する — **絶対最大 6 V**
- **NEVER** veto 回路の pulldown 抵抗を省略する — 起動中に消灯する事故になる
- **NEVER** 未確定の寸法・型番で確定させない。§7 は必ずユーザーに確認する
- **ALWAYS** 親リポジトリの doc を変更する前にユーザー承認を取る (親 `CLAUDE.md` §8.4)
- **ALWAYS** 全実装部品に LCSC 番号を設定する。ただし**秋月調達品は手はんだ前提で例外扱い**とし、
  その旨を BOM に明記する ([`docs/05`](05-jlcpcb-fab.md))
- **ALWAYS** ドキュメントに絶対パスを書かない (作業機が変わる前提)
</hard_rules>
