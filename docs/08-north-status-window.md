## 1. Goal / 何を作るか

<goal>
球体 (Isolation Sphere V2) の**北極キャップを、電源状態と充電状態が見える「ステータス窓」に作り替える。**

解決する問題は 2 つ:

1. **電源 ON/OFF が分からない** — 磁石をかざして電源を入れても、コントローラ (M5 AtomS 系) の起動に時間がかかるため、
   その間ユーザーは ON なのか OFF なのか判断できない。**ファームウェアに依存しないハードウェア表示**が必要。
2. **既存の指示 LED が見えない** — [`docs/06`](06-power-switch.md) §3.6.2 の電源 ON LED と
   [`docs/02`](02-ip2326-module.md) §3.5 の充電中 LED は**どちらも電源基板上 = 球体コアの中**にあり、
   外殻に埋まって視認できない。**北極キャップへ移設する。**

加えて **「再生が始まったら消灯する」** — コントローラがコンテンツ再生を開始したら、
ステータス窓を消して演出の邪魔をしない。これは ESP32 からの veto 線 1 本で実現する (§4.3)。
</goal>

## 4. Electrical specification / 電気仕様

### 4.1 System context (前提となる電源アーキテクチャ)

```
2S LiPo ──> [XR-2S-30A BMS (基板外)] ──> PACK_P (6.0-8.4V)
                                            │
                        ┌───────────────────┼──────────────────┐
                        │                   │                  │
                   [IP2326 充電]      [HT7333-1 LDO]     [MP1584 降圧]
                   CHG_IN=南極磁気端子   3.3V 常時オン        EN 制御で ON/OFF
                        │                   │                  │
                    pin6=充電LED        ┌───┴───┐            V5V (5V/3A)
                        │               │       │                │
                        │          ホール素子  [D-FF]            └─> AtomS + LED 800
                        │           (北極)   Q=電源状態
                        │                       │
                        └──────────────> 北極ステータス窓 <───────┘
```

**重要**: 3.3 V LDO は**常時オン**。だから電源 OFF 中でもホール素子と D-FF が生きていて、
かざした瞬間に反応できる。この構造が本 doc の前提。詳細は [`docs/06`](06-power-switch.md)。

### 4.2 北極 pillar を通る配線 — 5 本

| # | 信号名 | 方向 | 内容 |
| --- | --- | --- | --- |
| 1 | `V3P3` | 基板 → 北極 | 常時オン 3.3 V (ホール素子 + LED アノード共通) |
| 2 | `GND` | — | 共通グランド |
| 3 | `HALL_OUT` | 北極 → 基板 | ホール素子出力 (磁石検出) → D-FF の CLK |
| 4 | `STAT_PWR_K` | 北極 → 基板 | 電源 ON LED のカソード側戻り (基板側の MOSFET でスイッチ) |
| 5 | `STAT_CHG_K` | 北極 → 基板 | 充電 LED のカソード側戻り → IP2326 pin 6 |

- **線材: AWG30 級の細線 × 5**。Φ3 mm 通路に収まる
- **`HALL_OUT` は必ずツイストする** — 球内に WS2812 データ 5 本が走っており、
  40〜50 mm の引き回しはノイズを拾う。ホール出力はドライブされた低インピーダンスなので
  リードスイッチ (高インピーダンスのプルアップノード) よりは有利だが、対策は入れる
- 基板側に **RC ローパス** (例 1 kΩ + 1 nF) を入れる

### 4.3 電源 ON LED の駆動 + 再生開始で消灯する仕組み (veto)

**電流制限抵抗と LED はキャリア基板に、スイッチング素子は電源基板に置く。**
これにより pillar を通る線が 1 本 (カソード戻り) で済む。

```text
  V3P3 ──┬── R_LED 680Ω ── LED_PWR ──┐            [キャリア基板 = 北極]
         │   (Vf 2.0V → 2.0mA)        │
         │                            │  STAT_PWR_K  (pillar 経由)
  ═══════╪════════════════════════════╪═══════════════════════
         │                            │            [電源基板]
         │                       Q_LED.drain
         │                       (2N7002)
         │                            │
         │                          GND
         │
         │        Q (D-FF 出力) ── R 10k ──┬── Q_LED.gate
         │                                 │
         │        VETO 信号 ── R 10k ────── Q_VETO.drain
         │                      │           (2N7002)
         │                      │                │
         │                 R 100k              GND
         │                 (pulldown・省略不可)
         │                      │
         └───────────────────── GND
```

**この骨格 (Q で点灯 / VETO で消灯) は 3 案共通。違うのは `VETO` 信号をどこから作るかだけ。**

#### ⚠️ 制約: M5 AtomS3R は GPIO を使い切っている (2026-08-11)

当初案の「ESP32 の GPIO 1 本で veto」は**使えない**。代替 3 案を比較する。

| | **案 A: WS2812 データ活動検出** | 案 B: I2C GPIO エキスパンダ | 案 C: RC タイムアウト |
| --- | --- | --- | --- |
| GPIO 消費 | **0** | **0** (既存 I2C バスに相乗り) | **0** |
| firmware 変更 | **不要** | 必要 (1 bit 書くだけ) | **不要** |
| 追加部品 | 6 点 (すべて既存 BOM の型番) | IC 1 個 + 受動数点 + アドレス管理 | **4 点** |
| 消灯タイミング | **WS2812 へフレームが流れ始めた瞬間** | firmware が決めた任意の時点 | 電源 ON から固定時間後 |
| 意味的な正しさ | **「再生を始めたら」とほぼ一致** | 最も正確 (任意の条件で制御可) | 近似 (起動が遅れると先に消える) |
| リスク | データ線への負荷 (要高インピーダンス設計) | I2C バスが GPIO として使われていると成立しない | 起動時間のばらつきを吸収できない |

**推奨は案 A。** GPIO も I2C も firmware も使わず、しかも「再生が始まった」という
意味そのものを直接検出できる。

#### 案 A の回路 (WS2812 データ活動検出)

```text
  WS2812 DIN ──[R1 100k]──┬──[D1 1N4148W]──┬── V_ACT ──[R3 10k]── Q_ACT.base
   (3.3V, 800kbps)         │                │                      (MMBT3904)
                           │              C1 100nF                      │
                        (高インピーダンス   │                    Q_ACT.collector
                         タップで          R2 1M                        │
                         信号品質を        │                       VETO ノード
                         乱さない)        GND
```

- データが流れている間 `C1` が充電され `V_ACT` が上がる → `Q_ACT` が ON → VETO 成立 → 消灯
- データが止まると `R2 × C1 = 100 ms` で放電 → VETO 解除 → 点灯
- **しきい値は NPN の Vbe = 0.6 V** にする。MOSFET の Vth (2N7002 で 1.0〜2.5 V の 2.5 倍ばらつき)
  に依存させない — [`docs/06`](06-power-switch.md) §3.6.4 と同じ設計方針
- **部品はすべて既存 BOM の型番を流用できる**: MMBT3904 = `C20526` / 1N4148W = MP1584 の
  BST ダイオード `D3` と同型 / 抵抗・コンデンサは 0603 の既存品番
- オフ時電流は **0** (`V_ACT` が 0 V なので `R2` に電流が流れない)

⚠️ **案 A の意味論に注意**: 検出しているのは「**firmware が WS2812 フレームを送出している**」で、
「コンテンツを再生している」ではない。**firmware が待機中も黒フレームを流し続ける実装だと、
待機状態でも消灯する。** ファームウェアの挙動を確認して判断すること (§7 V3)。

#### 動作表 (案 A の場合)

| 状態 | Q | VETO | LED |
| --- | --- | --- | --- |
| 電源 OFF | L | L | **消灯** |
| **かざした瞬間 〜 AtomS 起動中** | **H** | **L** (データ未送出) | **点灯** ← 解決したい問題 |
| フレーム送出開始後 | H | **H** | **消灯** |
| 送出が 100 ms 以上途切れた | H | L | 点灯 (異常の可視化にもなる) |

**boot-safe が最重要要件**: `R 100k` の pulldown が無いと `VETO` ノードが不定電位になり、
起動中に消灯する事故が起きる。**どの案を選んでも pulldown は省略不可。**

### 4.4 ESP32 インターフェースと GPIO 拡張

<constraint>
**M5 AtomS3R は GPIO を使い切っており、veto 線も電源オフ線も割り当てられない (2026-08-11)。**
必要な信号は 2 本:

| 信号 | 方向 | 用途 | 現在の扱い |
| --- | --- | --- | --- |
| `VETO` | AtomS → 基板 | 再生開始でステータス窓を消灯 (§4.3) | 本 doc で新設 |
| `PWR_OFF` | AtomS → 基板 | ソフト電源断 (D-FF の CLR を引く) | [`docs/06`](06-power-switch.md) §1 で**ペンディング / パッド予約のみ** |
</constraint>

#### 拡張方法 3 案

| | **案 1: I2C GPIO エキスパンダ** | 案 2: WS2812 データ線に多重化 | 案 3: コントローラを載せ替え |
| --- | --- | --- | --- |
| 追加 GPIO の消費 | **0** (既存 I2C バスに相乗り) | **0** | — |
| 得られるビット数 | **4〜8 本** (将来の拡張余地つき) | 1 本相当 | 多数 |
| 部品 | IC 1 個 + パスコン (I2C プルアップはバス側に既存) | R + D + C + NPN ≈ 4 点 | — |
| firmware | I2C 書き込み (M5Unified で容易) | `digitalWrite(HIGH); delay(100);` のみ | 再検証が必要 |
| 決定性 | **高い** (任意のタイミングを明示的に制御) | 中 (レベル判別に設計余裕が必要) | 高い |
| 前提 | **I2C バスが空いていること** ← §7 Q5 | WS2812 線を電源基板まで引くこと | 親プロジェクトへの影響大 |

**推奨は案 1。** `VETO` と `PWR_OFF` を 1 個の IC でまとめて供給でき、
**§4.3 の案 A (データ活動検出・6 点) が不要になる**ため、部品点数でも有利になりうる。
余りビットは将来の状態通知 (`PWR_STATE` 出力など) に使える。

- 候補 IC: **PCA9570** (4 bit・出力専用・極小パッケージ) / **PCA9536** (4 bit・SOIC-8) /
  **PCF8574** (8 bit・LCSC 在庫が最も潤沢) — 品番と在庫の確定は §7 V7
- **電源は「電源 ON 中の系」から取ってよい** — `VETO` も `PWR_OFF` も
  システムが ON のときだけ意味を持つ信号なので、**オフ時電流には影響しない**
- ⚠️ `PWR_OFF` は D-FF の **CLR (アクティブ Low)** を引く。
  `H` ノードは Q2 の B-E で ~0.7 V にクランプされる構成ではなくなったので、
  **CLR のレベル整合を [`docs/06`](06-power-switch.md) 改訂時に確認する**

#### 案 2 の詳細 (I2C が使えなかった場合の代替)

WS2812 のプロトコルでは **High が最大 ~0.9 µs (T1H) しか続かない**。
したがって **数十 ms continuous High は通常動作では絶対に発生しない** → 一意な合図として使える。

- firmware は該当ピンを `HIGH` にして 100 ms 保持するだけ
- 基板側は RC ローパス + NPN で「持続 High」を検出 → `PWR_OFF` を生成
- ⚠️ **通常のフレーム送出との判別に設計余裕が必要**: WS2812 のビット列はデューティ
  33〜66% なので、RC の整定値が全ビット 1 のときと持続 High で近づく。
  **しきい値の余裕を計算で裏取りすること**。余裕が取れない場合は案 1 に戻る

### 4.5 充電中 LED

- IP2326 **pin 6** が駆動 (充電中点灯 / 満充電消灯 / 異常点滅を IC が自動判定)
- アノードを `V3P3` (常時オン) から取ることで、**電源 OFF 中の充電でも点灯する**
- 直列抵抗はキャリア基板側に置く。値は pin 6 の駆動形式が確定してから決める (§7 Q2)

### 4.6 ホール素子

| 候補 | 消費電流 | Bop | パッケージ | 調達 | 備考 |
| --- | --- | --- | --- | --- | --- |
| **ABLIC S-5716A** | **4.0 µA typ** (両極, tcycle 50.50 ms) | 1.8 / 3.0 / 3.4 / 4.5 / 7.0 mT から選択 | SOT-23-3 | **秋月 116980 系 ¥60** | 感度の高い品種が取れれば有利。出力は Nch OD / CMOS 選択可 |
| TI DRV5032FA | 1.6 µA (3V, 20Hz) | ±4.8 mT | TO-92 / SOT-23 / X2SON | LCSC C3716252 $0.18 | TO-92 あり (ただしキャリア基板を作るので不要) |

**どちらを採用するかは §7 Q1 で決める。** 消費電流の差 2.4 µA は
MP1584 のシャットダウン 12 µA に対し無視できるので、**判断軸は感度と調達性**。

## 5. Mechanical specification / 機構仕様

### 5.1 北極キャップ

- 現行: 黒 PETG の**純粋装飾蓋**、pillar へ**スナップ留め** (中央ねじなし)
- 変更: **透光させる**。方式は 2 案 (§7 Q4 で決定)
  - 案 a: **半透明 PETG / 自然色 PETG で別造形** — 部品追加ゼロ、造形色を変えるだけ
  - 案 b: **黒キャップ + ライトパイプ** — 意匠を黒で統一できるが部品が増える
- ⚠️ 外殻を黒にしているのは **LED ラッパ穴の遮光マスク**目的なので、
  北極キャップの透光化はその規則に抵触しない (極には LED が無い)
- **キャップは着脱式のまま維持する** — ホール素子と LED は**キャップではなく pillar 先端の
  キャリア基板に載せる**。こうすればキャップを開けても配線を触らない

### 5.2 pillar 先端キャリア基板

| 項目 | 仕様 |
| --- | --- |
| 搭載部品 | ホール素子 (SOT-23-3 または TO-92) / LED × 2 (0603 想定) / 抵抗 × 2 (0603) |
| 外形 | pillar 先端に収まるサイズ。**pillar 径から決まる** — 親 `docs/01-shell-cad.md` を要確認 |
| 固定 | **接着剤禁止**。ねじ or スナップ or pillar 先端の圧入座 |
| 配線 | 5 本を半田付け (またはコネクタ)。pillar 内通路へ引き込む |
| 実装 | **手はんだ可能な構成** (5 部品)。JLCPCB PCBA に出すかは §7 Q1 と連動 |

### 5.3 ホール素子の向き

- **磁石は北極の真上 (極軸方向) から近づく**
- ホール素子は**感磁面を極軸に対して垂直**に置く (磁束が素子面を貫くように)
- リードスイッチとは向きの考え方が違うので注意 (リードは長軸方向が高感度だった)

### 5.4 北極 pillar の配線通路

- **Φ3 mm の内部通路を新設** (南極 pillar と同じ手法)
- 構造荷重には影響しない — 案 K_new で pillar はクランプ荷重を受けないため

## 7. 着手前に解消すべき判断 / Decisions required before starting

<open_questions>
**この 4 件はユーザー判断。推論で埋めてはならない ([`CLAUDE.md`](../CLAUDE.md) §3)。**

- **Q1: ホール素子を S-5716A (秋月・手はんだ) と DRV5032 (LCSC・JLCPCB 実装) のどちらにするか。**
  キャリア基板を JLCPCB で実装させるなら DRV5032、手はんだなら秋月品で足りる。
  - 未確認の技術事項: 秋月の `S-5716ACDH0-M3T1U` は商品ページに「動作磁束密度 0.9 mT / 0.3 mT」
    「アナログ出力」と記載されているが、**ABLIC データシートの Bop 選択肢は 1.8/3.0/3.4/4.5/7.0 mT で
    出力はデジタル (OD / CMOS)** で一致しない。**ABLIC のパーツリストで実際の品種を確定させること**
- **Q2: IP2326 pin 6 (LED 出力) の駆動形式** — シンク (オープンドレイン) かソースか。
  直列抵抗値とアノードの取り方が決まる。データシートで確認 ([`docs/02`](02-ip2326-module.md))
- **Q3: 音 (ブザー) を追加するか。** 現状は**保留で光のみ**。
  追加する場合はワンショット回路 ≈ 5 点 + **コア内の容積確保**が必要 (親 Q31 に申し送り)
- **Q4: 透光キャップの方式** — 半透明 PETG 造形 (案 a) か 黒 + ライトパイプ (案 b) か
- **Q5 (ブロッカー): M5 AtomS3R の全ピン割り当てを出してもらう。**
  **GPIO は使い切っている**と判明しており (§4.4)、次が決まらないと veto と `PWR_OFF` の
  方式を選べない:
  - **I2C バス (Grove ポート等) が空いているか** — 空いていれば §4.4 案 1 (GPIO エキスパンダ) が最善
  - WS2812 の 5 本はどのピンか — §4.4 案 2 を使う場合、そのうち 1 本を電源基板まで引く必要がある
  - IMU 用の内部 I2C バスに外部デバイスを追加できるか (アドレス衝突の有無)

**技術的な未確認事項 (調査で潰せる)**

- **V1: 磁石の選定と動作距離の実測** — 外殻 5 mm + 隙間 = 合計 6〜8 mm を隔てて Bop を超えられるか。
  **計算より実測が速い。** ホール素子と一緒にネオジム磁石を数サイズ購入して測る
- **V2: 磁石を製品 BOM に載せるか**、ユーザー手持ち運用にするか
- **V3: AtomS の起動時間の実測 + フレーム送出の挙動** — 起動から最初の WS2812 フレームまでの時間。
  **待機中も黒フレームを流し続ける実装かどうか** (§4.3 案 A の意味論に直結)
- **V4: ~~veto に使える GPIO の選定~~** → **GPIO 枯渇のため §4.4 の拡張方式選定に置き換え**。
  型番は **M5 AtomS3R** と判明 (親 `CLAUDE.md` Q2 の解消材料)。
  **5 並列 PIO/RMT 出力が要件**なので、AtomS3R でそれが成立しているかも併せて記録する
- **V7: GPIO エキスパンダの品番と LCSC 在庫** — PCA9570 / PCA9536 / PCF8574 のいずれか。
  I2C アドレス、パッケージ、`VETO` / `PWR_OFF` に使うビット割り当てを確定
- **V5: pillar 先端の実寸** — キャリア基板の外形が決まる。親 `docs/01-shell-cad.md` を参照
- **V6: HT7333-1 の入力電圧上限**が 2S 8.4 V に対し十分か (LCSC 表記 30 V を datasheet で裏取り)
</open_questions>

## 8. Acceptance criteria / 完了条件

- [ ] **磁石をかざした瞬間** (AtomS の起動を待たず) に北極が点灯する
- [ ] **起動中も点灯し続ける** — AtomS の GPIO が High-Z の間、pulldown で LED が生きている
- [ ] **再生開始で消灯する** — §4.4 で選んだ方式 (I2C エキスパンダ / データ活動検出 / タイムアウト) で消える
- [ ] **veto 経路が AtomS3R の GPIO を 1 本も新規に消費していない** (§4.4 の前提)
- [ ] **もう一度かざすと即座に消灯**し、電源が切れる
- [ ] **電池を挿した直後は消灯 (電源 OFF)** — D-FF の POR で保証
- [ ] **電源 OFF のまま充電すると充電 LED だけが点く**
- [ ] **南極の充電マグネットを着脱してもホール素子が誤反応しない**
- [ ] オフ時のシステム合計電流が **≤50 µA** (設計見込み: LDO 2.5 + ホール 1.6〜4.0 + D-FF ~1 + MP1584 12 + IP2326 0.7 ≈ **18〜21 µA typ**)
- [ ] **北極キャップを外しても配線を触らずに済む** (素子は pillar 側)
- [ ] **接着剤を 1 箇所も使っていない**

## 9. Hard rules / 厳守事項

<hard_rules>
- **NEVER** 接着剤・瞬間接着剤・エポキシで固定する (親プロジェクトの全損事故履歴)
- **NEVER** 連続動作型のホール IC (mA 級) を使う — オフ電流予算 50 µA を 100 倍超える
- **NEVER** ホールラッチ (bipolar latch) を使う — 磁石を裏返す操作が必要になり UX が成立しない
- **NEVER** MP1584 の EN を 2S レール (6.0〜8.4 V) に接続する — **絶対最大 6 V**
- **NEVER** veto 回路の pulldown 抵抗を省略する — 起動中に消灯する事故になる
- **NEVER** 未確定の寸法・型番で確定させない。§7 は必ずユーザーに確認する
- **ALWAYS** 親リポジトリの doc を変更する前にユーザー承認を取る (親 `CLAUDE.md` §8.4)
- **ALWAYS** 全実装部品に LCSC 番号を設定する。ただし**秋月調達品は手はんだ前提で例外扱い**とし、
  その旨を BOM に明記する ([`docs/05`](05-jlcpcb-fab.md))
- **ALWAYS** ドキュメントに絶対パスを書かない (作業機が変わる前提)
</hard_rules>
